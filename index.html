Alice pays Bob through a stealth address

Register, announce, fund, scan, and spend. Each transaction is checked against the values the plugin prepared.

Keys are shown on this page. Use test accounts. Payment secrets stay in memory and are cleared on refresh. A fresh random sender key is created for every page session.

  1. Connect to a chain
  2. Create or load Bob and register his meta-address
  3. Create or load Alice, then prepare, announce, and fund
  4. Bob scans the configured block range and spends the note

Buttons stay available so web and CLI participants can be mixed. If a prerequisite is missing, the action explains what to do next.

Deployment and scan range

For an existing Bob announcement, set the scan start block at or before that transaction. Leaving it blank starts after the latest block.

Verify custom deployment bytecode

Sepolia uses pinned hashes automatically. On other chains, provide hashes from a deployment you trust; otherwise the demo marks the contracts as unverified.

Keygen

The host derives a 32-byte keygen master at m/5564'/60'/0'/0'. Scheme 3 applies its domain-separated KDF with scheme ID, scheme name, and keygen index to produce 128 bytes:

keygen_seed(master, scheme_id = 3, scheme_name, index, 128) keygen_seed = spending_seed (32) ‖ viewing_seed (32) ‖ kem_seed (64)

Keygen outputs the spending public key, viewing public key, and ML-KEM-768 encapsulation key.

spending_pk = compress(spending_seed · G)
viewing_pk = compress(viewing_seed · G)
(ek, dk) = ML-KEM-768.KeyGen(kem_seed)
meta = spending_pk ‖ viewing_pk ‖ ek
